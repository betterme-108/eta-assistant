# 英语教学助手 English Teaching Assistant · 开发记录

> 本文档记录系统的开发迭代过程，作为"教师借助生成式 AI 自主开发智能教学工具"的过程性证据，供开发与应用报告引用。

## 项目定位（一句话）

教师拍照上传学生作业 / 试卷 → AI 分辨题目与学生作答、自动批改评分并收集错题 → AI 归因到 36 类错因本体库 → 教师确认 → 一键生成讲评课决策单（重点讲 / 不讲 / 个别辅导 / 二改追踪）。学生零参与、零感知。

## 迭代日志

### 品牌更名 · 英语教学助手 English Teaching Assistant（2026-09）

> 「小英助教 / Teaching Buddy」的「小英」易被误读为小学英语、与本系统面向的初中学段不符，「Teaching Buddy」语域偏轻、与专业批改工具及反标签化伦理定位不符，且"Buddy"并非「助教」的规范译法。经讨论改为直白、清晰、准确的「英语教学助手 / English Teaching Assistant」（英文缩写 ETA），英文名即「助教」的规范译法。内部标识同步改为 ETA 缩写：目录 eta-assistant、数据库 eta.db、日志 eta.log、留痕 eta-trace-*.jsonl、环境变量 ETA_DB（旧名 XIAOYING_DB / ERROR_RADAR_DB / ERROR_ATLAS_DB 仍可读取兼容）；v4.2 更名记录保留为历史。

### 关键开发决策（供报告引用）

1. **决策单"规则出数据 + AI 出策略"混合架构**：讲什么的取舍是教学专业判断，名单与数字由确定性算法产出（阈值可配、SQL 可追溯）才经得起追问；大模型只负责归因、练习生成与讲评执行策略（基于给定数据，硬性约束不编造数字），且失败不影响规则版决策单。
2. **批量录入的行格式用名册命中判定消歧**：三段行"学号\|题干\|作答"与"题干\|作答\|正确答案"存在歧义——首段形似学号串且全部在名册才作学号段；形似但有不在册的明确报错，宁可拒绝不静默错位（错位数据比缺数据危害大）。
3. **同题去重归因**：归因的输入只有（题干, 作答, 题型, 原文），与"谁错"无关——共性错误多人错只调一次 LLM，结果展开为每人一条；省钱省时且保证同类同题归因一致。
4. **教师改判优先写进 SQL 口径**：一切统计取 `COALESCE(teacher_override, category_id)`——不是界面承诺，是数据层铁律。
5. **反标签化落到路由层**：系统不存在"按学生输出评价/报告/排名"的 API 端点；上传大模型的 payload 不含学生标识（批量行首学号仅用于关联名册，进模型前已剥离）。
6. **真实 AI 单模式**：deepseek-v4-pro（OpenAI 兼容直连）+ MinerU OCR，key 未配置显式报错；自动化测试以桩注入替换 LLM/OCR 数据源，测试路径与生产路径一致。
7. **练习必须审校**：AI 生成练习一律 `draft` 状态，教师逐题通过后方可附入决策单。
8. **批改判定分层，AI 只负责拿不准的部分**：听写与客观题用确定性规则判卷——快、免费、可解释；AI 只用于短主观题对错、作文分维评分与总结建议；AI 失败置"待判定"由教师把关，绝不静默给分或静默入库。
9. **批改即收集**：判错的题在批改完成时直接写入错题库待确认，与手动录入共用归因/确认/统计全链路；同题同答复用归因缓存，全班共性错误只调一次模型。
10. **题型边界诚实声明**：系统无语音链路（不做 ASR/TTS），听力等音频类题目不在范围；拍照读名中的姓名只用于本机名册匹配，不进入任何模型请求——反标签化延伸到批改链路。
11. **信息架构跟随工作流而非功能清单**：导航按“批改 → 错题 → 讲评 → 班级”分组（v4.3 起七页），作业与考试批改共用引擎仅预设不同——两者的本质差别是场景与信息（exam_type），不是批改算法；低频页面用页内分段合并（错因分析、讲评备课），同时保留旧 hash 地址映射——重构导航不丢老用户书签。
12. **拍照批改的参考答案缺口用「AI 给建议 + 教师核对」补位**：学生照片里没有标准答案——解析时让 LLM 依据题目本身给出参考答案（suggested_answer），前端逐题可改，客观题缺答案提交前确认提醒；批改入口同样遵循“AI 给建议、教师把关”，且姓名只做本机名册匹配不进任何模型请求（反标签化延伸到拍照链路）。
13. **拍照批改 OCR 升级为双流管道（角色区分是根本问题）**：转录文本里题干/手写作答/批改符号混在一起无法区分，单靠换 OCR 模型解决不了。文档流（DOC_OCR_PROVIDER）只管印刷题干转录，dual 模式 MinerU + PaddleOCR 双转录互补（4 张真实样图实测：MinerU 手写括号作答召回约 3 倍、PaddleOCR 印刷挖空编号更稳，两份带通道标记交解析 AI 做“快通道为主、慢通道补漏”，单通道失败自动降级单转录）；作答流（ANSWER_VLM_PROVIDER）多模态直读原图只提手写作答与批改符号，按题号覆盖转录猜测（选项字母配选择题、词组配填空题消歧大题内重号），题号直读失败时用 qwen-vl-ocr 行坐标就近归属兜底；作答失败降级纯转录单流不阻断，作答置信度分级（视觉直读 high / 坐标归属 medium / 转录猜测 low）前端以“待核对”轻提示呈现供教师把关。
14. **批次是错题的第二主键，时间线维度贯穿而非页面各自为战**（v4.9）：“这次考得怎么样”和“全期趋势怎么样”是两个不同问题——错题的天然坐标是（班级，批次，学生），只按任务类型聚合会把两者混在一起。本轮把 batch_no 升级为跨页维度：db 层 _confirmed_filter 统一收口（多选 IN + 阶段范围 + 旧数据 COALESCE 回落），list_batches 一处聚合三页共用；讲评备课用多选 + 阶段（“只讲评这次期中”或“上学期”），确认与分析用单选；决策单把 scope_label 随快照留档——导出打印后仍能看出统计口径。日期上界的坑：created_at 是 ISO 含 T 字母，与拼空格的 23:59:59 字符串比较会错序，必须用次日零点 + `<`。

### AI 辅助开发方式

- 全部代码、本体库、测试、文档由教师以自然语言提出教学需求，借助生成式 AI 结对完成；教师负责本体库内容审定（36 类错因均对照人教版初中英语教材与中考考点）与教学规则终审。
- 测试驱动：每个核心模块配套 pytest（共 165 项），保证"他人复现 = 一条命令看到全部通过"。

## 已知边界（诚实声明）

- LLM 归因失败或类别非法（重试 1 次后）自动进入"待人工复核"而非硬判；测试套件以确定性桩注入替换真实 API，离线可复现。
- 真实模式下大模型偶发超时/解析失败时自动降级（归因置待复核、练习回退模板题库），不阻断教学流程；连续失败会提示教师检查 key 与网络。
- OCR 真实通道主推 MinerU（token 14 天有效，https://mineru.net/apiManage/token 申请），备选 PaddleOCR / 视觉模型 key；key 未配置时对应功能在页面显式报错（真实 AI 单模式，无演示降级）。拍照批改文档流可设 dual（MinerU+PaddleOCR 双转录互补，需两通道 key）或 qwen_vl_ocr（百炼坐标转录，需 DASHSCOPE_API_KEY）；作答流未配置时自动降级纯转录单流。
- 演示数据为脚本确定性生成（`seed_full.py` / `seed_demo.py`），真实数据需教师日常录入积累。
- 批改链路中 AI 判定失败或返回非法值 → 该题置"待判定"：不计分、不自动入库，由教师当场把关（系统不静默给分）；客观题判卷为纯本地规则，不受网络影响。
- 系统不涉及音频/语音处理（无 ASR/TTS 链路），听力等音频类题目不在题型范围；书面表达（作文）为 AI 分维评分，仅供教学参考，最终以教师确认为准。
